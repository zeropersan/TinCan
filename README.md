# TinCan 🥫

> 两个铁皮罐，一根线，就能说悄悄话。

**TinCan** 是一个跑在 PHP 虚拟主机上的极简私人聊天室。无数据库、无框架、无需构建，上传即用。同时提供现代化前端与功能机（WAP）前端，密码访问，多房间自由创建。

---

## ✨ 特性

- **零依赖部署**：纯 PHP + JSON 文件存储，不需要 MySQL、Redis 或 Composer
- **密码访问**：使用 `password_hash()` 哈希存储，源码泄露也看不到明文
- **自定义昵称**：登录时自取昵称，浏览器 Cookie 记忆，下次自动预填
- **多房间**：输入房间名即可创建，房间自动持久化
- **双前端**：
  - `index.php` — 电脑 / 智能手机，每 3 秒增量轮询，准实时
  - `wap.php` — 功能机专用，XHTML-MP 标准，**零 JavaScript**，手动点「更新消息」刷新
- **文件锁并发安全**：读写均使用 `flock`，写入采用 `ftruncate + fwrite`，避免半截文件
- **自动裁剪**：每房间最多保留 300 条消息，防止 JSON 无限膨胀
- **XSS 防护**：存储原始文本，前端用 `textContent` / `htmlspecialchars` 输出

## 🧱 技术栈与设计原则

| 项目 | 选择 | 理由 |
|---|---|---|
| 后端 | 原生 PHP（7.3+） | 虚拟主机兼容性最好 |
| 存储 | 每房间一个 JSON 文件 | 无需数据库，便于备份与迁移 |
| 并发 | `flock` 文件锁 | 无扩展依赖 |
| 正常前端 | 原生 JS + `fetch` 轮询 | 无框架，体积小 |
| 功能机前端 | 纯 PHP 渲染 + 表单 POST | 兼容极老 WAP 浏览器 |

设计原则：**能用一行解决的不写两行，能用一个文件的不拆成两个。**

## 📂 目录结构

```text
/chatroom/
├── config.php          # 全局配置、Session、工具函数
├── setup.php           # 首次初始化密码（用完务必删除）
├── api.php             # 聊天接口（JSON，仅正常前端使用）
├── index.php           # 正常前端（电脑 / 智能手机）
├── wap.php             # 功能机前端（WAP / XHTML-MP）
├── data/
│   ├── .htaccess       # 禁止直接访问
│   └── auth_pass.php   # 密码哈希（setup.php 自动生成）
└── rooms/
    ├── .htaccess       # 禁止直接访问
    └── *.json          # 各房间消息（自动生成）
```

## 🚀 快速开始

### 1. 上传文件

按上面的目录结构上传到虚拟主机，`data/` 与 `rooms/` 权限设为 **755**（若无法写入再临时改 777）。

### 2. 初始化密码

浏览器访问：

```
http://你的域名/chatroom/setup.php
```

设置访问密码后，**立即删除 `setup.php`**。

### 3. 开始聊天

| 场景 | 访问地址 |
|---|---|
| 电脑 / 智能手机 | `http://你的域名/chatroom/index.php` |
| 功能机 | `http://你的域名/chatroom/wap.php` |
| 指定房间 | `index.php?room=家庭` |
| 新建房间 | 页面顶部输入房间名并「进入」，发首条消息即创建 |

## 📱 使用说明

### 正常前端（`index.php`）

- 登录页可自取昵称，昵称保存在浏览器 Cookie，下次自动预填
- 顶部标签显示已有房间，点击即可切换
- 消息区每 3 秒自动轮询，只拉取增量，不会整屏跳动
- 顶部「✏️ 改名」可随时改昵称，「⬇ 到底部」快速跳到最新消息与输入框
- 支持回车发送

### 功能机前端（`wap.php`）

- 完全不含 JavaScript，采用 XHTML-MP 标准
- 发送消息后页面自动跳回（相当于刷新一次）
- **查看新消息必须点击「🔄 更新消息」按钮**——这是刻意的设计，功能机的自动刷新要么耗流量，要么不兼容
- 顶部「⬇ 跳到底部」使用 HTML 锚点实现，不依赖 JS
- 底部有改名表单、房间切换与新建入口

## 🔐 安全说明

| 项目 | 做法 |
|---|---|
| 密码存储 | `password_hash()` + `password_verify()`，默认 bcrypt |
| 密码文件 | 存放于 `data/auth_pass.php`，内含 `<?php` 头，即使被下载也不会显示明文 |
| 目录保护 | `data/`、`rooms/` 均放置 `.htaccess` 拒绝直接访问（Apache） |
| 用户输入 | 房间名 / 昵称白名单过滤，消息入库前转义、输出前再转义 |
| Cookie | `HttpOnly` + `SameSite=Lax`，HTTPS 下自动带 `Secure` |
| 身份归属 | 昵称真实来源是服务端 Session，Cookie 仅用于预填，无法伪造身份 |

> ⚠️ **Nginx 用户请注意**：`.htaccess` 在 Nginx 下无效。若无法添加 `location` 规则，建议把 `rooms/` 改成随机长目录名，或确保消息中不含敏感内容。

## ⚙️ 可调参数（`config.php`）

```php
define('MAX_MESSAGES', 300);          // 每房间最多保留的消息条数
define('USERNAME_COOKIE_DAYS', 365);  // 昵称 Cookie 有效期（天）
```

正常前端的轮询间隔在 `index.php` 末尾：

```javascript
setInterval(poll, 3000);   // 每 3 秒轮询一次
```

功能机 `wap.php` 展示的消息条数：

```php
$recent = array_slice($messages, -30);   // 只显示最近 30 条
```

## ❓ 常见问题

**Q：为什么功能机不能自动刷新？**
A：老 WAP 浏览器对 JS 支持极差，且自动刷新会持续消耗流量。手动「更新」按钮是最稳定、最省流量的方案。

**Q：消息会丢吗？**
A：单房间最多保留 300 条，超出自动删除最旧的。需要长期归档可定期备份 `rooms/` 目录。

**Q：能同时支持多少人？**
A：文件锁方案适合十几人的小圈子。若并发写入频繁，建议换 SQLite（PDO），前端逻辑无需改动。

**Q：忘记密码怎么办？**
A：删除 `data/auth_pass.php`，重新访问 `setup.php` 设置新密码（注意：这会重置，不会删除聊天记录）。

**Q：能部署在 Nginx 主机吗？**
A：可以，功能完全正常。只是 `.htaccess` 目录保护不生效，参考上方安全说明处理。

**Q：能改项目名吗？**
A：可以。`index.php` 与 `wap.php` 的 `<title>`、登录页标题中的「私人聊天室」替换即可。
